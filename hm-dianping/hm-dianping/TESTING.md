## 1. 快速执行

在 PowerShell 进入后端目录：

```powershell
Set-Location 'D:\shixi\girl shop\hm-dianping\hm-dianping'
```

先运行纯单元测试和前端逻辑检查：

```powershell
mvn test "-Dtest=PriorityOneTests"
node follow-page.test.cjs
```

再运行真实服务集成测试，需要本机 MySQL、Redis、RabbitMQ 运行：

```powershell
mvn test "-Dtest=PriorityIntegrationTest" "-Dpriority.integration=true"
```

集成测试使用独立的 `girl_shop_priority_it_<时间戳>` 数据库、RabbitMQ 专用队列及 Redis 专用键，结束后清理测试数据库、队列和键；不会清空现有业务数据。数据库账号需允许创建和删除测试数据库。普通 `mvn test` 不会自动启用这些集成测试。

应用已运行时，通过 Nginx 检查真实接口：

```powershell
mvn test "-Dtest=PriorityLiveSmokeTest" "-Dpriority.live=true"
```

预期 `Failures: 0, Errors: 0` 和 `BUILD SUCCESS`。报告在 `target/surefire-reports/`。Node 检查成功显示 PASS。

使用两个专用测试账号 A/B 手动验收（以下涉及发送，请使用可丢弃测试会话）：

1. 两个浏览器分别登录，A从B商品进入聊天；双方显示“实时连接已建立”。A发消息后B自动收到，会话摘要及导航未读更新，无需刷新。
2. B不打开当前会话时保持未读；B打开并显示消息后A看到已读。浏览器隐藏时不得仅因后台补拉标记已读；第三方账号不能读取或标记双方消息。
3. 在浏览器 Network 中清空请求，空闲观察超过30秒：只有 WebSocket 心跳，不应固定每5秒/15秒请求消息或未读接口。
4. 测试环境临时断开浏览器网络，恢复后自动连接并补齐期间消息；多次刷新/重连不重复插入已显示消息。持续断连只低频降级检查。
5. 模拟发送响应丢失，文本与商品引用保留，点击重试沿用发送编号；数据库同发送者同编号只有一条。相同编号改正文应被拒绝。
6. 同账号多个标签页检查未读同步；退出登录后旧连接关闭，票据重复使用、过期及非允许来源连接均失败。
7. 加载更早消息分页不跳动、不串联系人；未加载消息不被批量已读。新消息和通知同时发生时导航数量应最终与服务端一致。

实际浏览器已只读验证连接状态、历史消息、已读展示和无新增控制台错误；未向真实卖家发送测试消息。断网、并发及重试主要由自动化覆盖，多实例广播和生产压力不在本次验收范围。

手工流程：
1. 刷新首页，检查横向分类、清除筛选、更多筛选、加载反馈及390px双列布局。未登录点击AI入口应跳登录，登录后返回AI发布页。
2. 选择1至5张同一商品实拍图，补充尺码、价格和瑕疵，未同意提交时不能生成。上传失败时保留文字。
3. 未配置模型时显示明确说明，原始图片和文字可以转为手动草稿；不显示伪造的生成成功。
4. 配置模型后生成，检查分类、标题、描述；没有提供的价格、品牌等不应自动补齐，成色必须人工确认。多件商品及冲突信息应提示核对。
5. 刷新或重连后可恢复任务状态。相同内容网络失败后重试，不应重复创建任务；生成途中手动改草稿，AI不应覆盖。
6. 预览链接仅本人可访问，首页和搜索中查不到草稿。补齐字段后勾选核对，发布并跳转商品详情。重复提交或并发提交只能生成一件商品。
7. 删除草稿、任务超时、服务商拒绝或返回不完整JSON时，应保留原始资料或给出明确错误，不能泄漏密钥、服务商错误体。
