# 运行与维护

## 本地环境

当前默认配置用于本地演示；支付和短信仍是模拟功能。服务入口为 Nginx 8090，后端 8081，MySQL 3306，Redis 6379，RabbitMQ 5672。各标签页独立登录。

上传目录可以通过 `SHOP_IMAGE_ROOT` 覆盖。Nginx 的 `/imgs/` 路径需与其保持一致。Redis 和 Redisson 使用相同主机、端口、密码和逻辑数据库配置，避免分布式组件连到不同实例。

## 配置隔离

`application-prod.yaml` 提供环境变量连接模板。启用 prod 时必须提供 `DB_URL`、`DB_USER`、`DB_PASSWORD`、`REDIS_HOST`、`MQ_HOST`、`MQ_USER`、`MQ_PASSWORD`；可选设置 `REDIS_PORT`、`REDIS_PASSWORD`、`MQ_PORT`、`SHOP_IMAGE_ROOT`。

不要把真实密码写进 Git、测试报告或截图。默认本地账号不能直接用于公开部署。prod 模板不记录模拟验证码；此模板仅隔离连接信息，不代表已经接入真实短信和支付。

## 数据库迁移

- `tb_schema_migration` 记录版本、SHA-256 校验和及执行时间。
- V001：兼容补建订单隐藏、捡漏请求、上传资源表。
- V002：为买家评价增加可空图片字段。
- V003：新增持久缓存失效任务。
- 每次启动按版本执行，并用数据库连接级锁避免并发迁移。已执行版本的内容不能原地修改，后续变更应新增版本。
- MySQL DDL 并非完整事务回滚；每项迁移保持幂等。中途失败时先排查权限和日志，再重启执行。

升级前备份数据库并保存前端静态文件和可执行 JAR；不要运行带 DROP/DELETE 的初始化脚本来升级。回退必须将前端和后端恢复为同一兼容版本，保留新增表和可空字段，禁止用删表方式回退。回退异步下单实现前，需要确认没有尚未完成的预占请求，避免旧版本绕过新记录。

本次部署前的 JAR 备份为 `.runtime/previous-girl-shop.jar`，仅是后端备份，不能代替前端备份。重新打包前确认这个文件是否仍需要保留，避免覆盖有用的回退版本。

## 日志与巡检

- 常规日志：`.runtime/application.log`。
- 隐藏进程的控制台日志：`.runtime/backend.stdout.log`、`.runtime/backend.stderr.log`。
- 每个 HTTP 请求返回 `X-Request-Id`，日志包含同一编号。前端错误弹窗不显示编号；请求编号记录在浏览器控制台，排查时按编号搜索。
- 超过1秒的请求记录慢请求日志，不记录请求体、token 或查询参数。
- 默认 INFO 日志减少 SQL 调试输出；本地模拟验证码单独记录，prod 配置关闭此项。
- 后台巡检关注超时捡漏请求、超过30秒未清理的缓存任务和最近失败请求，异常状态变化时记录 WARN，恢复时记录 INFO。日志巡检不能代替外部告警平台或值班通知。

捡漏投递：默认每秒最多取10条，未确认投递每10秒再试；预占请求超过5分钟进入补偿。库存对账每轮最多100件，使用游标分批。商品详情的普通缓存和逻辑过期缓存使用不同版本键，逻辑缓存带物理过期兜底。

缓存失效与业务更新同事务写入 `tb_cache_eviction`；提交后尝试删除，Redis不可用时由后台重试。任务 generation 防止较早的重试误删除后续更新的任务记录。缓存重建和浏览统计使用有界线程池；浏览计数在过载时允许丢弃，交易数据不依赖该计数。

## 异常处理

1. 页面失败：记录请求编号，检查对应日志；区分请求失败和数据为空。
2. 订单/捡漏失败：按请求ID查看 `tb_flash_request`，核对同ID订单及库存。先恢复基础服务，由幂等投递和补偿处理，不手工盲目加库存。
3. 缓存问题：查看 `tb_cache_eviction` 积压及 Redis 连通性，恢复后确认任务清理，避免删除整个 Redis 数据库。
4. 消息积压：查看 RabbitMQ 的 `flash.request.v2.queue` 与死信队列，以及旧请求失败队列。不要清空业务队列，也不要未经核对批量重放。
5. 数据库异常：保留日志与备份，修复连接或迁移权限后复测。不要修改迁移校验和来绕过变更检查。

真实服务重启、网络故障、容量和压力测试应在独立环境执行。现阶段没有设置生产吞吐承诺。
# 第一批交易服务增量（V004）

启动时自动创建交易通知、私信、拉黑、物流、售后与操作记录、举报和商品草稿表，不清理原有业务表。迁移仍受版本校验和数据库锁保护；不要修改已执行的 V001–V004 文件。

已付款订单不再直接取消，需通过售后流程；发货需从交易服务提交物流。真实支付与退款、物流轨迹查询、举报审核和人工仲裁后台尚未接入。`RESOLVED` 表示本地模拟结案，不是支付渠道退款成功。`DISPUTED` 表示已登记争议并暂停订单操作，需要后续人工处理能力。

通知与订单变更同事务持久化。私信及导航未读数通过 WebSocket 变更事件同步，健康连接空闲时不轮询 HTTP；连接失败时才降级为每60秒检查。旧消息链接自动跳转到 messages.html。举报与售后凭证沿用登录上传和图片归属校验。草稿图片标记为已使用，删除草稿不会删除原图片文件，以免影响复用图片。


## 实时消息部署（V005）

V005 为私信增加可空的客户端消息编号、请求指纹、发送幂等唯一索引及双向消息游标索引；保留既有记录。启动执行迁移前备份数据库，禁止修改已执行迁移文件。

消息仍通过 HTTP 校验权限并持久化到 MySQL；事务提交后 WebSocket 推送变更事件，客户端按消息游标读取新增记录。WebSocket 不替代消息存储，也不减少正常发送所需的持久化写入。未读数发生变化时按需读取并合并并发请求；健康空闲连接只有心跳，不查消息表。

Nginx 的 `/api/ws/messages` 必须使用 HTTP/1.1 并转发 Upgrade/Connection，关闭缓冲；修改配置后先执行 `nginx.exe -t`，成功再执行 `nginx.exe -s reload`。HTTPS 站点自动使用 wss。

允许来源默认是 `http://localhost:8090,http://127.0.0.1:8090`；新增访问域名时用环境变量 `SHOP_WEBSOCKET_ALLOWED_ORIGINS` 配置逗号分隔的完整来源（协议、主机、端口），避免通配来源。连接使用登录接口签发的30秒一次性票据，主登录 token 不放入连接网址；该 Nginx 路径关闭访问日志，避免记录票据。

客户端每25秒心跳，超时自动关闭；重连退避最长约30秒加随机偏移，重新签发票据并补拉。浏览器回到前台、恢复网络时也补拉。持续无法连接时每60秒降级检查，仅在可见页面执行。退出登录或会话失效会关闭对应连接。

当前连接路由位于单个后端进程内，适用于本机单实例。多实例部署前须增加跨实例事件分发（例如 Redis Pub/Sub）；事件只能用于提醒，漏事件仍须通过持久消息补拉恢复。尚未做容量压测，不承诺生产并发量，也未引入消息归档或删除策略。

## 商品与消息体验更新（V007）
V007 在私信表中新增可空 images 字段，保留历史消息。更新后需在 IDEA 停止并重新运行后端，启动自动执行增量迁移。前端静态文件刷新即可加载；请勿同时启动另一个 JAR 占用 8081。
私信支持最多5张 JPG/PNG 图片，客户端单图限制5MB，服务端继续执行真实图片及归属校验。图片发送复用消息幂等键，失败保留当前会话图片；纯图片消息在联系人中显示“[图片]”。
编辑页使用商品所有者权限接口判断捡漏配置是否可改；禁用时跳过捡漏写入，不影响普通商品保存。后端原有订单及预占校验继续生效。
交易通知展示订单快照与已登记物流；读取已读状态失败不阻断订单跳转。当前仍未接入外部实时物流轨迹。
搜索支持空格分词、温柔风归一，以及风格前缀与常见服装品类拆分，采用全部词匹配；不是任意语义搜索。

## AI辅助发布与首页改版（V008）

入口：`http://localhost:8090/ai-publish.html`。预览：`listing-preview.html?draft=<草稿ID>`，必须登录且属于该用户；未经确认不会生成商品记录。首页沿用本地Nginx，不迁移托管。

### 配置与启用
在 IDEA Run Configuration 的 Environment variables 中设置 `SHOP_AI_API_KEY` 和 `SHOP_AI_MODEL`，模型必须支持图片输入及 Responses API 的 strict JSON Schema。密钥只存服务端环境变量，不能放在前端或提交到源码。可选 `SHOP_AI_ENDPOINT`（默认 `https://api.openai.com/v1/responses`，只允许HTTPS）和 `SHOP_AI_DAILY_LIMIT`（默认每用户滚动24小时10次）。使用其他兼容服务时先确认它同时支持图片输入、Responses格式和严格结构化输出；Chat Completions-only接口不能直接使用。

停止 IDEA 中的后端后重新运行，自动执行 V008 增量迁移，新增 `tb_ai_listing_job` 和 `tb_draft_publication`；保留原有商品、订单和草稿。前端 Ctrl+F5 刷新。不要同时启动另一个 JAR 占用8081。没有密钥或模型名称时，生成入口明确降级为保存原始图片和说明、手动完善，不会伪造AI结果。

### 任务与发布
用户明确同意后，才会提交图片与说明。仅读取当前用户上传目录内经过校验的JPG/PNG，每张最多5MB，总计20MB，最多5张；图片作为data URL发送，服务商无需访问本机地址。调用设置store=false，但这不是对服务商全部数据保留政策的承诺。未确认的品牌、尺寸及价格等字段留空；成色仅依据卖家原文中明确且无冲突的声明（如“九成新”）映射到预览选项，不根据图片或使用次数推断，模糊、否定或冲突时待确认。价格仅接受用户说明中明确金额，最终仍需本人确认。

任务先持久化原始草稿，后台有界线程池最多2个并行调用，HTTP连接超时10秒、读取超时60秒。不自动重试付费调用；用户重试创建新任务并计入限额。QUEUED任务在重启后继续执行，RUNNING任务超过3分钟标记失败，原始草稿保留。WebSocket推送任务状态变更，页面加载与重连补查，实时连接异常时才每15秒兜底查任务状态，另有手动刷新入口。

相同用户和请求编号具有唯一约束，并验证请求内容指纹。生成后只做条件更新，用户在等待时编辑或发布的草稿不会被AI覆盖。确认发布对草稿加行锁，并通过唯一发布记录保证重复或并发提交只返回同一件商品。已发布草稿保留供幂等重试，默认不再列入可编辑草稿箱。

### 验证边界
本轮使用Mock HTTP验证Responses请求结构，用模拟模型与隔离MySQL验证持久化、权限、原始输入保留、防覆盖与并发发布。没有调用真实付费模型；需要配置后用自己的商品图片完成一次真实模型验收，再评估识别质量与耗时。正式发布仍依赖项目既有RabbitMQ上新通知，RabbitMQ不可用时应先恢复依赖。

参考接口：[OpenAI Responses API](https://developers.openai.com/api/reference/resources/responses/methods/create)。

### AI配置预检、百炼兼容与草稿重试更新
配置接口现在校验密钥、模型、HTTPS协议和完整的/responses路径；未就绪时拒绝创建任务，不产生失败草稿或消耗本地调用配额。北京地域endpoint须为完整的https://<业务空间ID>.cn-beijing.maas.aliyuncs.com/compatible-mode/v1/responses，不能只填写域名或业务空间ID。
百炼使用其文档规定的text.format.json_schema层级；OpenAI保留原始text.format结构。兼容单元素数组形式的模型输出，多商品数组不作为单件商品发布。所有结果继续经过后端字段校验，不把服务商的结构化输出当作事实准确性的保证。
失败重试使用retryJobId复用同一份草稿。若原草稿已被修改，前端需确认覆盖，后端再次校验overwriteConfirmed；已发布草稿不能重试。失败卡片不显示预览入口，成功卡片显示预览及草稿箱定位入口。草稿箱显示图片、状态、缺失字段并支持返回定位。
真实接口验收命令：mvn test "-Dtest=AiListingLiveTest" "-Dai.live=true"。该检查会调用配置的外部模型并可能计费，仅发送程序生成的服装示意图和测试文字，不发送客户照片、不发布商品；默认测试不会运行它。本轮已获取真实模型返回，不等同于用户商品照片的完整质量评测。

### AI发布工作台预览与基础地址兼容
右侧改为商品详情预览，READY状态读取本人草稿并展示图片、价格、分类、尺码、成色及描述；预览读取失败可独立重试，不改变任务成功状态。等待和失败状态不展示成功草稿。
接口配置现同时支持 `shop.ai.base-url` 与原 `shop.ai.endpoint`；基础地址以 `/v1` 结尾时自动追加 `/responses`，完整 `/responses` 地址不会重复追加，兼容尾部斜杠。`base-url` 优先于 `endpoint`。这与Python OpenAI SDK接受base_url后自行构造请求路径的用法一致。仅填写域名或业务空间ID仍会被拒绝。
RabbitMQ的“Failed to check/redeclare auto-delete queue(s)”需结合前后日志排查。本机日志当前为连接127.0.0.1:5672被拒绝，应启动RabbitMQ服务/容器并确认端口映射；不应通过关闭监听器掩盖故障。模型调用、草稿生成不依赖RabbitMQ，但项目既有正式商品发布后的上新通知使用它。

### 商品生成 Skill 与失败诊断

生成规则位于 `src/main/resources/skills/product-listing/SKILL.md`，由 AiListingClient 作为 system 消息加载，随应用打包。修改后需要重新编译并重启后端。该文件是应用运行时的商品生成 Skill，不依赖 Codex 自动发现。

分类通过当次数据库分类 id 枚举约束，成色限定为空交由卖家确认；其余事实仍经过 AiListingService 校验。Skill 不能保证模型绝对准确，也不能解决网络故障。预览必须以任务 READY 和本人草稿为依据。

AI 连接等待为 10 秒，读取等待为 120 秒，任务仍受 3 分钟过期保护；不自动重试付费调用。失败日志只记录任务 id、异常类型与 DNS_FAILED / TLS_FAILED / NETWORK_TIMEOUT / CONNECTION_FAILED 分类，不记录密钥、响应正文或用户图片。

历史仅有 ResourceAccessException 的日志无法回溯判断是哪一种底层故障。排查应以新日志为准。实时测试 `AiListingLiveTest` 需显式开启 `-Dai.live=true`，只发送合成图片，不发布商品。
